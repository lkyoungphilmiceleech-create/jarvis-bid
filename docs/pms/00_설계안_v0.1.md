# JARVIS PMS 설계안 v0.1 (초안)

> 공공기관 입찰용역 수행사 전용 프로젝트 관리 시스템. 질문·답변을 거치며 버전을 올린다.
> 변경 이력은 하단 `변경 이력`에 누적한다.

## 1. 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| P1 | 유연한 뼈대, 고정된 핵심 | 계층·필드·항목은 자유롭게 바꾸되 금액·공정률·마감 계산 규칙은 고정 |
| P2 | 과업변경이 기본값 | 과업 추가·삭제·금액 변경을 '예외'가 아닌 정식 이벤트(변경 이력)로 처리 |
| P3 | AI와 분리 | 웹/앱 단독 동작. AI는 선택형 부가기능(API)으로만 연결 |
| P4 | 입력은 한 번, 보는 곳은 여러 곳 | 한 데이터를 표·보드·타임라인·캘린더 뷰로 전환(노션 방식) |
| P5 | 개선이 일상 | 앱 내 피드백 → 이슈 → 배포 → 변경로그 사이클 자동화 |

## 2. 생애주기 (입찰 → 정산)

```
입찰공고(collect.py 자동수집) → 검토/Go-NoGo → 제안 → 수주·계약
 → 착수(과업지시서 분해) → 수행(업무·요청·비용) → 중간/최종보고
 → 준공·정산(선금·기성·잔금) → 사후(평가·레퍼런스)
```

기존 `data/latest.json` 입찰공고를 '영업 파이프라인'으로 불러와 수주 시 프로젝트로 전환한다.

## 3. 데이터 모델 (핵심 엔티티)

```
Organization(발주기관)
 └ Contract(계약: 계약금액, 기간, 선금/기성 조건, 과업변경 이력)
    └ Project(프로젝트) ── parent_id로 하위 프로젝트 무제한 중첩
       └ WorkItem(과업항목: 과업지시서 조항, 가중치=배정예산)
          └ Task(실행업무: 담당, 마감, 상태, 체크리스트)
BudgetLine(예산 비목) ↔ Expense(집행: 증빙파일, 비목, 연결 WorkItem)
Request(조직원 간 업무요청: 요청자→수행자, 기한, 수락/반려/완료)
Milestone(보고회·납품·검수 등 법정/계약 마감)
ChangeLog(모든 핵심 필드 변경 이력) / CustomField(JSONB 사용자 정의 필드)
```

## 4. 핵심 계산 규칙

- **공정률** = Σ(WorkItem 가중치 × 완료율) / Σ 가중치. 가중치 기본값은 과업 배정 예산.
- **집행률** = 누적 집행액 / 예산.
- **위험 신호** = 집행률 − 공정률 > 임계치(예: 15%p), 마감 D-7 미완료, 요청 미응답 48h.
- **선금 정산**: 선금은 계약금액의 70% 이내, 기성·준공 대가 지급 시 정산(정부 입찰·계약 집행기준).

## 5. 화면 구성

1. 포트폴리오 대시보드: 전체 프로젝트 공정률·집행률·위험·매출 인식 현황
2. 프로젝트 대시보드: 과업 트리, 간트/타임라인, 예산 대비 집행, 마일스톤
3. 내 업무: 오늘/이번 주 마감, 받은 요청·보낸 요청
4. 정산: 비목별 예산·집행·증빙 누락 체크, 발주처 제출 양식 출력
5. 영업 파이프라인: 수집된 입찰공고 → 검토 → 제안 → 수주

## 6. 기술 구성 (권장안, 확정 전)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js + PWA | 웹·모바일 설치형 동시 지원 |
| DB/인증 | PostgreSQL(Supabase) + RLS | 행 단위 권한(대표/PM/실무/외부협력사) |
| 파일 | 오브젝트 스토리지 | 증빙·산출물 보관 |
| 알림 | 이메일/Slack/카카오 알림톡(선택) | 마감·요청 알림 |
| 배포 | GitHub Actions → 스테이징 → 운영 | 지속 개선 파이프라인 |

## 7. 지속 개선 체계

- 앱 내 `피드백/오류 신고` 버튼 → GitHub Issue 자동 생성(라벨: bug/개선/질문)
- 2주 단위 릴리스, `CHANGELOG.md` 및 앱 내 '새 소식' 공지
- DB 스키마는 마이그레이션 파일로만 변경(데이터 유실 방지), 자동 테스트 통과 시에만 배포
- 월 1회 사용 지표 리뷰(미사용 기능 제거, 반복 요청 기능 추가)

## 8. 단계별 로드맵(안)

| 단계 | 기간 | 범위 |
|---|---|---|
| 0. 검증 | 2주 | 실제 진행 중 프로젝트 1건으로 데이터 모델 검증(시트/노션) |
| 1. MVP | 6~8주 | 프로젝트 계층, 과업·업무, 공정률, 마감, 업무요청, 대시보드 |
| 2. 정산 | 4주 | 예산·집행·증빙, 선금/기성 정산, 제출 양식 출력 |
| 3. 연결 | 4주 | 입찰공고 파이프라인, 알림, 캘린더 연동 |
| 4. 고도화 | 상시 | 선택형 AI(요약·위험 예측), 리포트 자동화 |

## 9. 미결 질문 (Q&A로 확정)

- Q1. 사용자 수·역할 구분, 외부 협력사 접근 여부
- Q2. 정산 기준: 발주처 제출 양식/시스템(예: e나라도움 등) 및 사내 회계 연동 여부
- Q3. '하위 프로젝트'의 실제 단위(예: 한 용역 안의 마켓·행사별)
- Q4. 과거 솔루션 이탈 지점(무엇이 불편했나)
- Q5. 개발·운영 주체(사내 개발자 유무)와 호스팅 조건
