# MICELEECH PMS 설계안 v0.9

> 공공기관 입찰용역 수행사 전용 프로젝트 관리 시스템. 질문·답변을 거치며 버전을 올린다.
> 변경 이력은 하단 `변경 이력`에 누적한다.

## 1. 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| P1 | 유연한 뼈대, 고정된 핵심 | 계층·필드·항목은 자유롭게 바꾸되 금액·공정률·마감 계산 규칙은 고정 |
| P2 | 과업변경이 기본값 | 과업 추가·삭제·금액 변경을 '예외'가 아닌 정식 이벤트(변경 이력)로 처리 |
| P3 | AI와 분리 | 웹/앱 단독 동작. AI는 선택형 부가기능(API)으로만 연결 |
| P4 | 입력은 한 번, 보는 곳은 여러 곳 | 한 데이터를 표·보드·타임라인·캘린더 뷰로 전환(노션 방식) |
| P5 | 개선이 일상 | 앱 내 피드백 → 이슈 → 배포 → 변경로그 사이클 자동화 |

## 2. 생애주기 (입찰 → 정산)

```
입찰공고(collect.py 자동수집) → 검토/Go-NoGo → 제안 → 수주·계약
 → 착수(과업지시서 분해) → 수행(업무·요청·비용) → 중간/최종보고
 → 준공·정산(선금·기성·잔금) → 사후(평가·레퍼런스)
```

기존 `data/latest.json` 입찰공고를 '영업 파이프라인'으로 불러와 수주 시 프로젝트로 전환한다.

## 3. 데이터 모델 (핵심 엔티티)

```
Organization(발주기관)
 └ Contract(계약: 계약금액, 기간, 선금/기성 조건, 과업변경 이력)
    └ Project(프로젝트) ── parent_id로 하위 프로젝트 무제한 중첩
       └ WorkItem(과업항목: 과업지시서 조항, 가중치=배정예산)
          └ Task(실행업무: 담당, 마감, 상태, 체크리스트)
BudgetLine(예산 비목) ↔ Expense(집행: 증빙파일, 비목, 연결 WorkItem)
Request(조직원 간 업무요청: 요청자→수행자, 기한, 수락/반려/완료)
Milestone(보고회·납품·검수 등 법정/계약 마감)
ChangeLog(모든 핵심 필드 변경 이력) / CustomField(JSONB 사용자 정의 필드)
```

## 4. 핵심 계산 규칙

- **공정률** = Σ(WorkItem 가중치 × 완료율) / Σ 가중치. 가중치 기본값은 과업 배정 예산.
- **집행률** = 누적 집행액 / 예산.
- **위험 신호** = 집행률 − 공정률 > 임계치(예: 15%p), 마감 D-7 미완료, 요청 미응답 48h.
- **선금 정산**: 선금은 계약금액의 70% 이내, 기성·준공 대가 지급 시 정산(정부 입찰·계약 집행기준).

## 5. 화면 구성

1. 포트폴리오 대시보드: 전체 프로젝트 공정률·집행률·위험·매출 인식 현황
2. 프로젝트 대시보드: 과업 트리, 간트/타임라인, 예산 대비 집행, 마일스톤
3. 내 업무: 오늘/이번 주 마감, 받은 요청·보낸 요청
4. 정산: 비목별 예산·집행·증빙 누락 체크, 발주처 제출 양식 출력
5. 영업 파이프라인: 수집된 입찰공고 → 검토 → 제안 → 수주

## 7. 지속 개선 체계

- 앱 내 `피드백/오류 신고` 버튼 → GitHub Issue 자동 생성(라벨: bug/개선/질문)
- 2주 단위 릴리스, `CHANGELOG.md` 및 앱 내 '새 소식' 공지
- DB 스키마는 마이그레이션 파일로만 변경(데이터 유실 방지), 자동 테스트 통과 시에만 배포
- 월 1회 사용 지표 리뷰(미사용 기능 제거, 반복 요청 기능 추가)

## 10. 정산 장부 · 자동 연동 설계

### 장부(Ledger) 한 줄 구조
일자 · 적요 · 거래처 · 공급가/부가세/합계 · 통화/환율 · 결제수단(법인카드/계좌이체/개인카드 선지급) · 증빙유형(세금계산서/카드전표/영수증) · 첨부 · 프로젝트/하위 프로젝트/과업항목 · 정산비목 · 결재상태 · 출처(수동/카드/결재)

### 법인카드 자동 삽입
- 수단: 카드 데이터 중계 API(예: CODEF 법인 승인·청구내역, 14개 카드사 지원) 또는 카드사 직접 API(예: 우리카드 법인카드 이용내역)
- 흐름: 매일 자동 수집 → **'미분류함'** 적재 → 모바일에서 한 번 눌러 프로젝트·비목 지정
- 자동 분류 규칙: 카드 소지자의 '현재 출장 프로젝트', 가맹점→비목 학습 규칙(규칙 기반, AI 불필요)
- 해외 결제: 승인 시점 금액은 '가확정', 청구내역 수신 시 원화 확정액으로 자동 갱신

### 메일플러그 전자결재 연동
- 공개 확인된 API는 SSO·조직도 연동 수준이며 전자결재 API는 미확인 → 메일플러그 문의 필요
- 1안(즉시 가능): 결재 완료 알림 메일을 전용 수신 주소로 자동 전달 → 파싱해 장부 반영(결재번호로 중복 방지)
- 2안(역방향): 앱에서 지출 입력 → 지출결의서 본문·첨부 자동 생성 → 메일플러그에 붙여 상신
- 3안(API 확인 시): 결재 상신·완료 이벤트 직접 수신

## 11. 입력 최소화 · 가시성 원칙
- 입력은 자동 수집(카드·결재·입찰공고)과 템플릿(프로젝트 유형별 과업 세트)이 기본, 사람은 '분류·확인'만
- 상태 변경은 1탭, 주간 진행은 과업항목별 한 줄 메모
- 대시보드는 '지난주 대비 변화'(공정률 증감, 새 지연, 새 요청)를 첫 화면에 표시

## 12. 무(無)운영 스택 (사내 개발자 부재 대응)
- 관리형 서비스만 사용: 웹 호스팅(Vercel 등) + 관리형 PostgreSQL/인증/파일(Supabase, 서울 리전 우선)
- 모든 계정은 회사 명의, 코드·설계·운영 문서는 GitHub 저장소에 보관(개발 연속성은 저장소 문서로 보장)
- 변경 절차: 이슈 → Claude 개발 → 자동 테스트 → 미리보기 URL → 승인 후 운영 반영, 일 단위 자동 백업, 오류 자동 수집

## 13. 모바일 · 해외 현장 모드
- PWA(홈 화면 설치)로 시작, 필요 시 앱스토어 포장(Capacitor)
- iOS 제약: 푸시는 홈 화면 설치 시에만(iOS 16.4+), 백그라운드 동기화 불가 → 앱을 열 때 대기 중 입력 일괄 전송
- 현장 모드 화면: 오늘 일정·체크리스트, 경비 사진 등록, 업무요청, 미분류 카드내역
- 시간대: UTC 저장, 현지시간+KST 병기

## 17. 지출 입력 경로
1. **구글 시트 불러오기(법인카드)**: 서비스 계정에 시트 공유 → 정기 동기화 + '지금 가져오기' 버튼. 원본 행 ID로 중복 방지, 프로젝트 미지정 건은 '미분류함'으로. (Sheets API 한도: 프로젝트당 분당 읽기 300회·사용자당 60회 → 20명 규모에 충분)
2. **앱 직접 입력(송금·온라인 결제·개인카드)**: 모바일 3단계 폼(금액·지급형태 → 프로젝트·항목 → 증빙 사진), 해외송금은 통화·환율 입력
3. **전환 계획**: 초기엔 시트를 유지하고 앱이 읽기만 함 → 안정화 후 앱 직접 입력으로 일원화, 필요 시 시트로 역내보내기

## 18. 경영진 대시보드 (첫 화면 5블록)
1. 프로젝트별 공정률 (지난주 대비 증감)
2. 문제점·해결안: 이슈 로그(문제, 영향, 해결안, 담당, 상태, 보고일) 미해결 우선
3. 주요 마감·일정: 14일 이내 마감, 지연 표시
4. 예산: 집행액·집행률·수익금액·수익률 (권한자만 표시)
5. 인력 배치: 사람 × 프로젝트 매트릭스(역할, 기간, 부하)

## 22. 과세 금액 입력 규칙 (구현: `pms/src/lib/money.ts`)
- 과세 칸 입력 모드: **총액(기본)** / 공급가액. 공급가액이 따로 적힌 증빙이면 모드 전환
- 총액 입력 시: 공급가액 = 총액 × 10/11 (원 미만 반올림 기본, 절사·절상 설정 가능), 부가세 = 총액 − 공급가액 → 항상 공급가액 + 부가세 = 총액
- 공급가액 입력 시: 부가세 = 공급가액 × 10%
- 합계 = 과세(공급가액) + 영세, 부가세는 같은 행 별도 칸. 취소·환불(음수)도 대칭 처리

## 26. 외화(영세) 송금 규칙 (구현: `money.ts` convertToKrw·remittanceNote)
- 입력: 통화, 현지 송금액, 송금일 기준 환율(기준일·종류), 수수료 목록(송금수수료·전신료·중계은행수수료 등)
- 영세(원화) = 현지 송금액 × 환율 ÷ 고시단위, 원 미만 반올림. 엔화 등은 100단위 고시 자동 적용
- 비고 자동 문구 예: `USD 1,234.56 × 1,385.20원(2026-09-01 전신환매도율) = 1,710,113원 / 송금수수료 10,000원, 전신료 8,000원 (수수료 계 18,000원)`
- 통장 실제 출금액이 환산액과 다르면 영세를 실제 출금액으로 수정 가능(차액은 비고에 기록)
- 외화 건은 환율·기준일 없이 저장 불가(DB 제약)

## 27. 법인카드 공용 시트 가져오기

- 행의 프로젝트 표기 ↔ PMS 프로젝트 별칭 표(`project_aliases`): 'KOCCA', '해외마켓', 'VivaTech' 등 표기가 달라도 연결. 모르는 표기는 미분류함

## 28. 호스팅 결정: '구글 중심 + 표준 DB + 이관 보장'

## 33. 계약금액 분리 · 산출 승인 흐름 (구현: 0004)

## 38. 이슈 해결 처리 (구현: 0005)
- `effective_pm()`: 프로젝트에 PM이 없으면 상위 프로젝트 PM
- '해결됨' 전환·재오픈은 PM(또는 관리자)만, 해결 일시·해결 내용 기록. 진행 상태 변경은 누구나
- '내 업무'에 **내 프로젝트 이슈(PM)** 섹션 → 해결 내용 입력 후 해결 처리

## 39. 알림 (구현: 0005 + `src/lib/notify.ts` + `/api/cron/notify`)
- 이벤트 → 발송함(`notifications`) 적재 → 서버 작업이 10분마다 발송
  - 새 업무요청 → 받는 사람 / 요청 수락·반려·완료 → 요청한 사람 / 이슈 보고 → 프로젝트 PM / 마감 D-1·D-DAY(매일 08:00 KST) → 담당자
- 채널: 이메일(회사 SMTP, 메일플러그) · 카카오워크 Bot(`messages.send_by_email`)
- 사용자별 설정(`/settings`): 채널 켜기/끄기, 카카오워크 계정 이메일(다를 때만)
- 실패 시 최대 5회 재시도, 마감 알림은 중복 방지 키로 하루 1회
- 알림 적재 함수는 사용자가 직접 호출할 수 없음(타인에게 임의 알림 방지)
